## Report: the theme collection

(The third coder agent of 2026-09-29 worked in a git worktree of its own and left no transcript file; this is its final report as it reached the planning session.)

Context: CabinetOS, the creator's card "Develop 30 most world popular theme for CabinetOS". The themes are a marketplace collection, not part of the core (Article 10, the Zero-Bloat Foundation).

## Built
- **36 theme files** in `sdk/themes/collection/`: 27 dark and 9 light.
  - They cover **28 of the creator's 30 entries**. 27 entries have files; Nord already ships in the core.
  - 9 files are extra variants: GitHub Light, Ayu Mirage, Ayu Light, Solarized Light, Gruvbox Light, Noctis Lux, and Catppuccin Latte, Frappé and Macchiato (Mocha ships in the core).
  - **Left out:** #20 City Lights, because its license (CC BY-NC-ND 4.0) forbids derived works such as a port. #27 Dainty: its license is MIT, but its colours were generated by a package that is no longer published, and no public file holds them.
  - IDs: github-dark, github-light, one-dark-pro, dracula, material-theme, ayu-dark, ayu-mirage, ayu-light, monokai, night-owl, one-monokai, tokyo-night, solarized-dark, solarized-light, winter-is-coming, gruvbox-dark, gruvbox-light, shades-of-purple, cobalt2, noctis, noctis-lux, catppuccin-latte, catppuccin-frappe, catppuccin-macchiato, panda, synthwave-84, atom-one-light, darcula, sublime-material, palenight, omni, snazzy-light, matcha, houston, horizon-dark, horizon-bright.
  - Every file has `version` 1.0.0, `author` "<palette author>, port by CabinetOS", and an `attribution` naming the source and license. The theme schema has no `description` field, so the descriptions live in the marketplace catalogue.
- **Licensing:**
  - Every colour was read from the theme's own public repository at a pinned commit. Nothing is from memory, so nothing is marked "to verify".
  - All 30 license files were read at the same commits. All are the plain MIT text, with two exceptions noted in `NOTICES.md`: Shades of Purple adds "anything you build with this should also be MIT licensed" (CabinetOS is MIT, so this is met), and gruvbox has no license file (its README says MIT/X11, its package.json says MIT).
  - Monokai is the classic scheme that VS Code ships under MIT; Monokai Pro is not used.
  - Darcula comes from rokoroku's MIT community port.
- **`NOTICES.md`**: for each theme, the source and the files read, the copyright line, the license, and the version and commit. It also lists what the port derives, what was not used and why, and the MIT text.
- **`README.md`** (collection): a table of ID, name, kind and source by list rank, the mapping rules, and the contrast of each theme.
- **`marketplace.csv`**: one row per theme with `id`, `license`, `source` and `description`.
- **`build-index.ps1 -Collection`**: packs each collection theme as a `theme` item, in the CSV's order. Each item has the CSV's description, license and source (as `author.url`, which the marketplace view's Source button opens), plus `minCoreVersion` 0.1.0 as the shipped themes have. Without the switch the output is unchanged. The build stops when a theme has no CSV row, a row has no file, a row is listed twice, or a shipped ID is repeated.
- **`docs/themes.md`**: a line in "At a glance", a new section "The collection" (what it is, why it is not in the core, how to install one, the local index, how the colours were chosen, how to add a theme with its notice), and the first "Not yet" line updated.

**Contrast, measured as the window draws text.** Row names are drawn at 90 %, row details and the status bar at 76 % of `textSecondary`, and dialog text at 80 %. They are measured on the pane, on a hovered row, on a selected row, on the backdrop, and on the menus, the dialogs and the terminal. Rule: body text at least 4.5:1; tertiary text at least 4.5:1 plain and at least 3:1 as a hint. **36 of 36 pass.** Lowest body-text contrast per theme (the weakest place is always row details on the selected or hovered row): atom-one-light 4.86, ayu-dark 4.72, ayu-light 4.68, ayu-mirage 5.03, catppuccin-frappe 4.54, catppuccin-latte 4.66, catppuccin-macchiato 4.98, cobalt2 4.80, darcula 4.90, dracula 4.80, github-dark 5.33, github-light 5.26, gruvbox-dark 4.68, gruvbox-light 4.86, horizon-bright 8.31, horizon-dark 5.73, houston 4.94, matcha 4.58, material-theme 5.17, monokai 5.03, night-owl 4.68, noctis 4.68, noctis-lux 4.67, omni 5.05, one-dark-pro 4.87, one-monokai 4.87, palenight 4.73, panda 4.53, shades-of-purple 5.30, snazzy-light 4.51, solarized-dark 4.56, solarized-light 4.51, sublime-material 4.57, synthwave-84 5.79, tokyo-night 4.71, winter-is-coming 6.63.

## Decided (what, because, undo)
- `-Collection` is an opt-in switch, not the default — because `ui/CabinetOS.Tests/EndToEndTests.cs:375` expects exactly 4 themes in the default local index — undo: make it the default and update that test.
- Per-theme marketplace data goes in `sdk/themes/collection/marketplace.csv` — because the theme schema has no description field, and a `.json` side file in the folder would be read by the core as a broken theme; the build fails when the CSV and the files disagree — undo: delete the CSV and put the descriptions elsewhere.
- The CSV `source` becomes the index item's `author.url` — because the marketplace view's Source button then opens the original theme's repository — undo: drop the `$Url` line in `Add-ThemeItem`.
- Mica tint = the darkest of the source's editor, side bar and panel backgrounds, at 0.9; the panes are the next surface colour at `80`; light themes use the same rule — undo: edit `mica.tint` and `layerFill` in the files.
- The three Catppuccin flavours map roles exactly as the shipped Mocha does (tint = base) — because the family should look alike — undo: edit the three files.
- Contrast is measured as the window draws text, not on the raw colour values — because `ThemeMapper` dims row details to 76 % — undo: relax the rule and restore each theme's own muted colours (listed in the collection README).
- Order of text choices: another colour of the theme's own palette first, then its main text at a lower alpha, and only then the smallest move toward white or black (for Solarized, toward base3 or base03) — undo: edit the text keys.
- Terminal colours: the theme's own; ANSI colours a theme leaves unset (SynthWave '84, Horizon) take VS Code's own defaults (MIT); themes with no terminal colours (Atom One Light, Darcula, Material Theme, Sublime Material) get colours built from their syntax colours; Horizon Bright's cursor is its editor cursor — undo: edit `terminal`.
- Substitute sources: Material Theme from Mattia Astorino's MIT Sublime Text repository (the VS Code repository now redirects to a commercial successor with no license); Panda from the author's MIT Atom and Hyper themes (the VS Code port states no license); Sublime Material from JarvisPrestidge's port — undo: swap the files and their notices.
- `noctis-lux` added as the warm variant of Noctis — because the creator's note says "warm and cold variants" — undo: delete the file and its rows.
- Accents where a theme has several signature colours: Night Owl `#C792EA` (its button purple gives only 3.6:1 under the design's `#111111` text on accent buttons); also Monokai `#F92672`, Panda `#FF75B5`, SynthWave '84 `#FF7EDB`, Darcula `#CC8242`, Omni `#988BC7`, Houston `#4BF3C8`, Snazzy Light `#09A1ED`, Gruvbox Light `#D65D0E` — undo: edit `accent`.
- Snapshots: neutral demo folders and no terminal; the picker picture is cropped — because the WebView2 data folder cannot be moved to scratch, and the full picker picture was over 400 KB — undo: retake them.

## Needs the creator
- City Lights (#20): its license forbids ports. Keep it out, ask Yummygum for permission, or pick a replacement theme.
- Dainty (#27): its generated colours no longer exist in any public file. Accept 28 of 30, or pick a replacement.
- Publishing: the collection reaches users only when the public index exists (ADR 0012). Run `build-index.ps1 -Collection` there or copy the folder.
- Darcula's premise needs a check: JetBrains' Darcula scheme is in intellij-community under Apache-2.0, an open license. If the creator wants JetBrains' exact colours, that source is allowed; the MIT port was used as instructed.
- Readability or fidelity: some themes show brighter text than in VS Code (One Dark Pro and One Monokai `#D7DAE0`, Palenight `#EEFFFF`, both Solarized variants). The collection README lists every change to revert.

## Known gaps
- The terminal colours were not seen rendered: WebView2's data folder is fixed to the real `%LOCALAPPDATA%\CabinetOS\WebView2` (`WebViewHost.cs:60`), with no variable to move it. The terminal colours pass the core's parser and the contrast check.
- The design's accent buttons draw text in a fixed `#111111` (`CbOnAccentBrush`). On the dark accents of light themes this is below 4.5:1: GitHub Light 3.64, Catppuccin Latte 3.49. WinUI's own accent buttons use white text there.
- Accents that are pale on light panes, measured as UI elements: Ayu Light `#F29718` 2.20:1, Snazzy Light 2.72:1 (the themes' own colours).
- Focus borders on some light themes are faint (Catppuccin Latte 1.97:1; the design's own default is about 1.7:1).
- In a few themes the tertiary text is the main text at an alpha, so the three text levels differ only by alpha.
- The collection had no automated test in the repository at the time of this report (the core agent added one later the same night).

## Noticed out of scope
- By the same as-drawn measure, two shipped themes fall short: Nord's tertiary text is 3.69:1 plain, and Rosé Pine Moon's row details are 4.44:1 on the selected row.
- `CbOnAccentBrush` could follow the accent's lightness instead of staying fixed.
- A variable such as `CABINETOS_WEBVIEW2_DIR` would let tests and live checks open the terminal without writing into the real folder.
- A CI check that validates `sdk/themes/collection` against the schema would guard future additions.
