CabinetOS: a developer-first file manager for Windows 11

Total Commander's operational power with VS Code's workspaces, terminal, command palette and extensibility, delivered as a native Fluent application. This handout accompanies the clickable prototype and explains what was built, why, and what is still open.

1. Principles

Low floor, high ceiling. The first-run experience is a single pane, a sidebar and an address bar. Every power feature (second pane, terminal, palette, editors) is one toggle or one shortcut away and leaves no trace when it is off.

Native first. Mica backdrop for the window, Acrylic only for transient surfaces (palette, context menu, flyouts, dialogs). Windows 11 list selection (3 px accent pill, translucent row fill), 4 px control radii, 8 px surface radii, standard caption buttons. No web-style chrome.

Commands are the product. Every action has an id, a category and a keybinding. Buttons, menus, the palette and plugins all call the same commands, so the UI stays consistent no matter where an action is triggered.

3. The views

A. Main workspace

Dual pane by default for the developer profile; the Dual / Single toggle in the command bar collapses to one pane. The active pane carries a brighter border and a white title; Tab switches focus. Workspace tabs sit in the title bar and drive the sidebar, the git branch in the status bar and the terminal's starting directory.

The terminal is a toggleable panel whose working directory follows the active pane. Three layout takes are switchable in the prototype's Tweaks:

  • Classic: sidebar left, terminal docked bottom. Most familiar to Total Commander users; widest file lists.
  • Terminal right: terminal as a third column. Keeps long file lists tall, suits ultrawide monitors.
  • Rail: VS Code activity rail (Explorer, Marketplace, Git, Terminal) with a collapsible panel. Best for plugin-heavy setups where the sidebar hosts many views.

B. Command palette

Ctrl+Shift+P opens an Acrylic overlay anchored 64 px below the title bar. Rows show Category: Command, a plugin badge when the command comes from an extension, and the binding as keycaps. Chords render as two keycaps joined by "then" (Ctrl+K then Ctrl+C). Hovering a row reveals a pencil; clicking it switches the row into recording mode, and the next keys pressed become the binding (a second combo within one second makes a chord, Esc cancels).

C. Marketplace

Replaces the pane area rather than opening a separate window, so it inherits the sidebar and status bar. Cards show author with a verified mark, rating and count, installs, and a Theme / WASM plugin label. Selecting a card opens a detail column with the requested capabilities listed up front. Install opens a permissions review dialog: each capability is rated low, medium or high, the sandbox is explained in one sentence, and the primary action reads "Allow and install". Themes apply immediately (accent and Mica tint) so the user sees the result without leaving the store.

D. Editors and context menu

Opening a Markdown or binary file replaces the other pane with an editor tab (Markdown Preview+, Hex Editor Pro). The tab strip shows the providing plugin and a close button that returns the pane to its folder. The right-click menu follows the Windows 11 pattern: an icon strip for cut, copy, paste, rename and delete, then labelled rows. Plugin actions are grouped under a "From plugins" heading with a source badge so users can always tell where an action came from.

E. File operations flyout

Copy operations run in a bottom-right Acrylic flyout: title, source → destination, a live throughput graph, percent, bytes done, ETA, Pause and Cancel. Minimising it leaves a compact progress pill in the status bar; the main UI is never blocked and panes stay fully interactive during the transfer.

5. Plugin trust model

Plugins are WebAssembly modules that declare capabilities in their manifest. The UI surfaces this in three places so the user is never surprised:

  1. Marketplace detail: "Requested capabilities" listed before the Install button is pressed.
  2. Review dialog: each capability rated low / medium / high with a plain-language reason, plus an opt-in to trust the publisher for updates.
  3. In use: every plugin-provided command, menu item and editor tab carries the plugin's name as a badge.

6. Open questions and next steps

  • Light mode and high-contrast variants of every surface.
  • First-run experience: how and when the single-pane user discovers the second pane, the terminal and the palette.
  • Pane types beyond folder, Markdown and hex (image, archive contents, remote drives) and how many editor tabs a pane can hold.
  • Conflict and error states for transfers: overwrite prompts, permission errors, network drops.
  • Keybinding conflicts: what the palette shows when a recorded shortcut is already taken.
  • Real Fluent iconography and Segoe UI Variable once the design moves into the native toolkit.
